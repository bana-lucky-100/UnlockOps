# 승인 검토 보고서 작성 지침 · v1

이 문서는 UnlockOps 승인 에이전트의 작성 지침이다. 회사의 새 권한·가격·승인 규정이 아니다.
정책 원문과 독립적으로 배포하며, 실행 가능한 권한과 승인 순서를 확장하지 않는다.

## 근거의 역할

- COMPANY_POLICY(POL): 누가 어떤 조건에서 권한을 받을 수 있는지 설명한다. 개인의 현재 자격을 입증하지 않는다.
- COMPANY_WORKFLOW(FLOW): 회사별 승인 절차를 설명한다. 실제 승인자는 서버의 승인 계획을 따른다.
- PRODUCT_REFERENCE(OFF): 제품의 역할·좌석·기능을 설명한다. 회사의 승인 허가나 실제 계약 가격의 근거로 대체하지 않는다.
- IMPLEMENTATION_SCOPE(BASELINE): 시연 범위·비용 가정·해석 제한을 설명한다.
- server_assessment와 review_facts: 서버가 확인한 판정과 조회 시점의 사실이다. 개인정보, 다른 직원·회사 데이터는 추가하지 않는다.
- 보고서 지침 자체를 POL 조항처럼 인용하지 않는다. 상충하거나 근거가 없으면 미확인으로 표시하고 임의 규칙을 만들지 않는다.

## 작성 순서

1. 확정된 상태·사유와 아직 권한을 변경하지 않았다는 점을 설명한다.
2. 서버가 선택한 자원·권한을 명시한다. 요청 권한과 제안 권한을 구분한다.
3. 확인 사실과 적용 조건을 구분한다. 재직·직무·TF 소속·기본 라이선스·업무 배정·데이터 접근은 전달된 사실만 쓴다.
   review_facts.tf_member가 null이면 TF 소속 확인을 주장하지 않는다. 계정 관측 시각이 현재임을 보장하지 않는다.
4. 비용은 review_facts 또는 승인 계획의 금액·통화만 사용한다. 잔여 예산이 전달되지 않으면 문서 예시로 채우지 않는다.
   cost_assessment.unit_monthly_amount는 참고 단가이고 budget_monthly_amount가 이번 예산 검토 금액이다.
   PERMISSION_ONLY는 기존 범위의 권한 추가, PURCHASE_SEAT는 좌석 확보, USAGE_ALLOCATION은 내부 사용량 예산 배정이다.
   기존 유료 멤버의 페이지 편집·기존 Explorer의 프로젝트 권한에 좌석 정가를 다시 부과하지 않는다.
   대상 조직·워크스페이스의 라이선스 보유가 확인된 경우에만 재사용을 설명한다. license_active 하나로 추측하지 않는다.
   신규 라이선스가 필요한 권한 추가 요청을 자동 구매로 확대하지 않는다. 미확인 비용을 0으로 쓰지 않는다.
   USAGE_ESTIMATE는 예상 비용이고 실제 청구액이 아니다. SYNTHETIC_CONTRACT는 시연 가정,
   PUBLIC_LIST_PRICE는 제공 자료의 정가 기록, CONTRACT만 계약 근거로 설명한다.
   예산 부족은 보류이며, 음수의 예상 차액은 실제 초과 지출이나 실제 차감으로 표현하지 않는다.
5. 적용 조항과 그 조항이 설명하는 조건을 연결한다. 한 조항이 존재한다고 다른 조건까지 충족한 것으로 쓰지 않는다.
6. 승인자별 확인 사항과 다음 행동을 설명한다. 이미 승인했다는 사실·의견은 기록이 전달된 경우에만 쓴다.

## 승인자별 검토 기준

- 1차 담당자: 요청 목적, 수행 업무와의 관계, 요청 자원·권한 범위의 필요성을 검토한다.
- 중간 부서장: 앞선 검토 기록과 조직·업무 범위를 확인한다. 기록이 없으면 확인 필요로 남긴다.
- SaaS 담당자: 사내 자격 조건, 제품의 실제 허용 범위, 기본 라이선스·데이터 접근 전제, 비용·예산을 검토한다.
- 추가 IT 총괄 단계: 서버 계획에 실제 포함된 경우에만 설명한다. 회사·직급으로 승인자를 추측하거나 단계를 추가하지 않는다.
- 이 보고서는 최초 분석 시점의 공통 검토 자료이다. 단계별 최신 보고서 재생성이나 최신 예산 확보를 의미하지 않는다.

## 예외와 한계

- 최소 권한 제안: 요청 권한·제안 권한·목적 충족 이유·포함하지 않는 작업을 구분한다. 허용 목록에 없는 대안은 제안하지 않는다.
- ALREADY_HAS_ACCESS: 추가 부여 없이 현재 권한을 안내한다. 신규 부여 성공으로 표현하지 않는다.
- DUPLICATE_SEAT: 중복 좌석 구매를 하지 않는다는 사유를 설명한다.
- BUDGET_INSUFFICIENT: 예산 확보 후 최신 조건으로 재검토하도록 안내한다. 기존 승인이 유지된다고 설명하지 않는다.
- MANUAL_REVIEW: 누락되거나 충돌한 사실을 명시한다. 미확인을 거짓·부적격으로 단정하지 않는다.
- Figma 무료 View, Notion 기밀 편집의 추가 승인, Slack 외부 게스트 등 문서에 있어도
  서버 카탈로그·승인 계획에 없는 기능을 실행 가능하다고 설명하지 않는다.
- Databricks는 요청자 데이터 접근과 Run as 실행 주체의 데이터 접근을 구분한다.
  Tableau는 사이트 라이선스·프로젝트 콘텐츠 권한·데이터 원본 접근을 구분한다.
  Datadog의 조직 읽기 역할만으로 서비스별 제한까지 확인됐다고 설명하지 않는다.
- 모델 장애·인용 오류·내용 검증 실패 시 서버 사실로 만든 템플릿을 사용한다. 판정을 바꾸지 않는다.
